# Lectern

PDF、手書き、YouTubeのページ内再生、レーザーポインターをまとめた講義用Webアプリです。React / TypeScript / Viteで実装し、GitHub Pagesで静的配信します。第1段階（ローカル保存版）です。クラウド同期・ログインは実装していません。

A4縦の講義ハンドアウトを基本にしています。サンプルもA4縦3ページです。iPadを横向きにしてもPDFの縦横比を保ち、全ページ表示と幅に合わせた拡大表示を選べます。白紙追加は現在のページサイズを引き継ぎ、既定値はA4縦です。A4以外のPDFも元のサイズと向きで読み込みます。

**公開先:** https://murajun620-crypto.github.io/lectern-notes/

## 使い方

1. 「PDFを読み込む」で教材を選択します。「3ページのサンプルで試す」でも全機能を試せます。
2. ペン・蛍光ペンで筆記し、色と太さを上部で調整します。消しゴムは円が通った部分だけを消します。上部のサイズ欄で直径8・16・28・48・80 pxを選べます。円は拡大中も画面上で同じ大きさになり、選んだサイズはペンとは独立して保存します。Undo / Redoはページ別に直近60操作を保持します（再起動すると履歴は消えますが、筆記は保存されます）。
3. 初期設定の「連続」では、指1本で上下にスクロールしてページをまたげます。下部の「ページ表示」で「1ページずつ」を選ぶと、指1本の横スワイプで前後のページへ移動できます。2本指はどちらのモードでも移動・ピンチ拡大縮小です。「移動」ツールを選んでいても、Pencilには直前の筆記ツールが適用されます。マウスでは「移動」ツールでドラッグできます。ページ表示の設定はこのブラウザに保存します。

   指1本で素早くスクロールして離すと、勢いに応じて少し進み、減速して止まります。もう一度指やPencilを置くとすぐに止まります。

4. 「選択」で筆記を囲むかタップすると、選択枠と操作メニューが出ます。枠内のドラッグで移動し、右下の角または「拡大」「縮小」で縦横比を保ってサイズを変えられます。コピー・切り取り・複製・削除もメニューから行えます。貼り付け先を指定するには、コピーや切り取りの後にページの空白をタップして「貼り付け」を押します。コピーした筆記は同じタブの別ページ・別資料にも貼り付けられます。指で枠や角を操作でき、枠の外では指で移動できます。
5. 「動画を挿入」にYouTube URLを貼り付けます。枠の初期サイズは横長160×90 pt、Shorts URLでは縦長90×160 ptです。中央の ▶ を1回タップすると配置したサイズで再生し、サムネイルのほかの部分をタップすると配置メニューが出ます。左端のつまみで位置、右下のハンドルや「−」でサイズ、回転ボタンで縦横を調整できます。用紙の外側にも配置できます。「動画を折りたたむ」で小さな再生ボタンになります。再生中に「閉じる」をタップするとサムネイルに戻ります。動画の外のページを指でタップすると、サムネイルに戻ると同時に配置メニューも開きます。
6. ツールバーの「全画面表示」でPDFの表示領域を広げます。選択中のツールを使い続けられ、動画の配置変更・挿入やページ一覧も利用できます。資料名・更新確認・書き出しは「資料メニュー」で開けます。「全画面表示を終了」で通常の表示へ戻ります。
7. ライブラリでは資料名の変更・複製・削除ができます。ページ一覧では白紙の挿入・削除・上下ボタンでの並べ替えができます。「書き出す」メニューから別PDFの全ページも追加できます。

ページ番号欄は番号を入力してEnterでジャンプします。表示方法は「ページ全体」「幅に合わせる」から選択し、倍率は100〜1000%で変更します。幅に合わせた縦長ページは指で上下に移動します。レーザーは触れて動かすだけで使え、軌跡は入力設定で切り替えます。レーザー選択中は上部の太さ欄がレーザー用に変わり、2・4・6・8・12 pxから選べます。太さは画面上で一定に保ち、ペンとは独立してこのブラウザに保存します。レーザーの位置・軌跡は保存しません。

ピンチ・移動中はPDF、筆記、動画を同じ座標で動かします。大きく拡大するか一定距離を移動したときは、画面とその少し外側の筆記を複数フレームに分けて描画し、完成した画像で表示を更新します。PDFは大きなピンチの途中で指の動きが緩んだときに先行描画します。指を離した直後は用意できた画像で最初のフレームを表示し、その後に必要な部分を描き直します。連続ページで表示の中心が隣に移るときも、描画済みの高精細画像を対応するページに残します。スキャン画像の細かさは元のPDFに含まれる画像の解像度に依存します。

ショートカット: `P` ペン、`M` 蛍光ペン、`E` 消しゴム、`S` 選択、`L` レーザー、`H` 移動、`←` / `→` ページ送り、`Ctrl/⌘ Z` Undo、`Ctrl/⌘ Shift Z` Redo、`Esc` 全画面表示を終了。選択ツールでは `Ctrl/⌘ C` コピー、`Ctrl/⌘ X` 切り取り、`Ctrl/⌘ V` 貼り付け、`Delete` 削除が使えます。

### Pencil・色・パーム抑制

筆記中は上下のバーやページ送りへの指・Pencilの誤タップを抑えます。「入力設定」の「下部バーを表示」をオフにすると、下部をPDFの表示に使い、ページ番号・ページ送り・表示方法・倍率は上部の「ページ・表示」から開けます。

「ペン」を選ぶと、上部の「ペンの種類」でボールペン、万年筆、鉛筆、筆ペンを切り替えられます。ボールペンは均一に近い線、万年筆は線の方向で太さが変わる線、鉛筆はざらつきのある線、筆ペンは入りと抜きのある線になります。選んだ種類はブラウザが覚え、各ストロークの種類も資料とバックアップに保存します。PDF書き出しにも線の違いが反映されます。

ペンと蛍光ペンに別々の3色プリセットがあり、ツールに合わせて切り替わります。蛍光ペンの初期色は黄色・ピンク・黄緑です。各色は「入力設定」で変更でき、設定はこのブラウザに保存します。筆記中にツールを切り替えると、そのツールで最後に選んだ色に戻ります。任意色のカラーピッカーも使えます。

太さもペンと蛍光ペンで個別に選べます。ツールを切り替えると前に選んだ太さに戻り、ページを再読み込みしても設定が残ります。

入力設定の「手のひらの誤操作を抑える」は既定でONです。Pencil使用中の指入力を無視します。Pencilより先に触れていた手のひらも、Pencil接触時点で移動操作を中断し、手を離すまで移動・スワイプに転用しません。大きな接触面の補助判定は実際のPencil使用直後だけに限定し、**Pencil未使用時に接触面の大きさだけで指を除外しません**。Pencilを離した後に新しく置いた指はすぐに移動・スワイプに使えます。「指でも筆記する」をONにした場合のみ、誤描画防止にPencil筆記後350msの待機時間を設けます。画面からフォーカスが外れただけではPencil使用後として扱いません。OSから接触情報が届かない場合は判別できないため、ネイティブアプリと同等のパームリジェクションを保証するものではありません。

「指でも筆記する」をONにすると1本指で筆記でき、「移動」ツールを選んでいた場合はペンへ戻ります。指の圧力は固定値で扱います。2本指を置くと筆記途中の線を取り消してピンチ・移動に切り替え、2本とも離すまで筆記へ戻しません。SafariのTouch Eventsでもピンチを処理し、Pointer Eventsとの重複適用を防ぎます。これはiPadと共通の入力処理の修正で、iPhone向けの専用UI最適化は行っていません。

画面への**2本指タップ**でペン／消しゴムを切り替えられます（入力設定でOFFにできます）。ピンチや2本指ドラッグでは切り替えません。

**Pencil Pro本体のダブルタップ／スクイーズはSafariの公開APIでは取得できません。** 画面上のダブルタップとは異なります。Appleの対応APIはネイティブの`UIPencilInteraction`／SwiftUI向けで、本体のジェスチャーに対応するには別途iPadネイティブアプリ化が必要です。[Appleの仕様](https://developer.apple.com/documentation/applepencil/handling-double-taps-from-apple-pencil)。

筆記はperfect-freehandの曲線描画を使います。Pencilも初期設定では指と同じ一定の太さで描画します。筆圧で太さを変える場合は「入力設定」の「Pencilの筆圧で線の太さを変える」をONにします。SafariではPencil専用のTouch EventsとPointer Eventsを照合します。離筆の通知と一緒に届いた接触中の移動も取り込みます。短い接触で移動の通知がなく、同じPencil接触の開始・終了位置が近いときは、その2点で短い線を描きます。Pencilを置いた直後は動きがあれば線を表示し、動きがない点は離筆で確定します。間隔が広い曲線は描画時に補間します。画面、サムネイル、PDF出力に同じ描画処理を適用します。

書いている線は独立したCanvasで変化した部分だけを更新します。離筆で1画を画面と元に戻す履歴に確定し、IndexedDBへの自動保存は最後の編集から300ms待ってまとめて行います。書き込みを始める直前に筆記中なら延期します。PDFの高精細化とプレビューの更新も筆記の合間に行います。消しゴムを動かしている間は通った部分だけを消し、指やPencilを離したときに1回の操作として確定します。レーザー軌跡は1本の曲線として描きます。

短い画が抜ける場合は、サンプル資料を開き、「入力設定」の「Pencil入力を記録」を押します。短い線を10本続けて書くか、症状が出る字を試してから「記録を終了して書き出す」を選びます。JSONにはPencilの入力時刻・各画の開始位置からの相対位置・確定した画の点数が入ります。記録は端末内で作成されます。

消しゴムは筆記ごとのページ座標に部分消しの範囲を記録し、PDF本体には適用しません。太い蛍光ペンも円の内側だけが消え、速いドラッグでは入力点の間も連続して消えます。後から書いた線は以前の消去範囲に影響されません。消した筆記を選択して動かすと消去範囲も一緒に動きます。部分消しは自動保存・再起動・PDF出力・バックアップに反映されます。

### ホーム画面と更新

Safariからホーム画面に追加した版は、安全領域と表示可能な高さに合わせてレイアウトします。「全画面表示」はブラウザが許可する場合にネイティブの全画面を使い、それ以外はブラウザの表示領域を広く使うレイアウトに切り替えます。

ライブラリと編集画面の**更新確認**は、キャッシュを使わず公開版の`version.json`を取得します。新しい版があると「保存して更新」で教材を保存してから新版を読み込みます。IndexedDBの資料や設定は削除しません。オフライン時はそのまま作業を続け、オンライン復帰後に再確認してください。更新確認ボタン追加前の版からは、最初に一度ページを再読み込みしてください。

## 保存・WindowsとiPadの移行

- PDFバイナリと編集データを別のIndexedDBストアに保存します。筆記・配置・ページ変更は操作後約300msで自動保存し、上部に状態を表示します。全画面表示で資料メニューを閉じている場合は、ツール列のチェックが保存済み、回転表示が保存中です。大きいPDFのバイナリを筆記のたびに書き直しません。
- 開いていた資料とページを再読み込み時に復元します。保存は**端末・ブラウザ・配信元URLごと**です。端末間では自動共有されません。
- 「書き出す → 編集可能なバックアップ」で `.lecture.zip` を保存します。元のPDF、全ページの筆記、並び順、動画ID・位置・サイズ・折りたたみ状態を含みます。
- ZIPをOneDrive、AirDrop、USBなどで相手の端末へコピーし、ライブラリの「バックアップを復元」で読み込みます。既存資料を上書きせず、新しい資料として復元します。
- バックアップは`project.json`（`format: lectern`, `version: 2`）と`assets/<id>.pdf`で構成します。旧version 1も読み込めます。部分消しを含む新版バックアップの復元先では、先にアプリを更新してください。形式・座標・動画ID・消去範囲・ZIP展開サイズを検証してから一括保存します。
- ブラウザのデータ消去、プライベートブラウズの終了、OSのストレージ削除で消えることがあります。定期的にバックアップしてください。保存失敗時はエラーを表示し、保存済みにはしません。
- 編集中の変更は同じタブで完了してください。同一資料の複数タブ同時編集には対応していません。

## PDF書き出し

「書き出す → 書き込み入りPDF」で表示中と同じページ順・向きのPDFを生成します。PDF表示と筆記を画像として合成するため、元のテキスト検索・選択、フォーム、リンク、アクセシビリティ情報は保持しません。通常2倍、長辺最大4096pxに制限してメモリ使用量を抑えます。長いPDF・大判ページは端末のメモリや出力時間の制約を受けます。

動画は用紙内に重なる部分を、クリック可能なYouTubeリンク枠としてPDFに出力します。用紙の外側を含む配置や再編集にはZIPバックアップを使ってください。

## iPad Safari・YouTubeの制約

- Safari 16.4以降を対象にビルドしています（最新のiPadOSを推奨）。`Promise.withResolvers`をpolyfillし、PDF.jsのworker・CMap・標準フォントは同じ配信元から読み込みます。古いSafari・組み込みWebView・すべてのPDFとの互換性を保証するものではありません。
- Pencilの筆圧は入力設定で有効にできます。初期設定と非対応入力では一定の太さを使います。OSの自動手書きテキスト化は実装していません。
- YouTube IFrame Player APIを使用し、`playsinline=1`、標準の再生・一時停止・シーク操作を利用します。サムネイル以外を勝手に外部アプリへ開きません。動画内のYouTube自身の外部リンクはYouTubeの仕様に従います。
- Safariのユーザー操作制約で初回再生が止まる場合、動画内の再生ボタンを再度タップしてください。埋め込みの内部表示領域を200×200 CSS px以上に保ち、プレーヤー全体を配置枠に合わせて表示します。拡大と「閉じる」は再生中に動画のそばに出ます。表示する余白がないときは上部ツールバーに出ます。
- 埋め込み禁止（101/150）、削除・非公開（100）、再生元確認エラー（153）、API取得失敗・タイムアウトには説明と代替リンクを表示します。代替リンクを選んだ場合のみ外部ページを開きます。動画終了でページ移動しません。
- YouTube再生にはインターネット接続が必要です。動画はバックアップにダウンロードしません。広告・ログイン・年齢・地域・配信者の制限は回避しません。
- レーザーは画面ミラーリングに映ります。AirPlay/HDMIの接続自体はiPadOSで行ってください。独立した発表者画面や外部ディスプレイ専用表示はありません。
- アプリ本体のオフライン起動用Service Workerは含みません。
- PDFは300MB / 2000ページ、ZIP入力は500MB・宣言展開サイズ750MBまでです。実際に扱える量は端末に依存します。パスワードPDFは解除してから読み込んでください。

## 開発・テスト

Node.js 22、pnpm 11を使用します。

```sh
corepack enable
corepack prepare pnpm@11 --activate
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm exec playwright install chromium webkit
pnpm test:e2e
pnpm build
pnpm preview
```

`predev` / `prebuild`でPDF.jsのCMap・標準フォントを`public/`にコピーします。生成されたファイルはGit管理外です。ビルド時の`VITE_BASE_PATH`はGitHub Actionsがリポジトリ名から自動設定します。手動ビルドでは未指定なら`./`になり、サブディレクトリ配信に対応します。

`pnpm test`はURL検証、ページ座標の線ヒット・選択、バックアップデータ検証を行います。Playwrightは実PDFを使って筆記・消去・選択・Undo/Redo・ズーム座標・再起動・ページ操作・ZIP移行・PDF出力・全画面での編集・動画配置・APIエラーを検証します。動画の統合テストではAPIをモックし、外部サービスに依存しないCIとしています。Chromiumではタッチのページ送り・ピンチ、接触面の広い指による筆記、筆圧イベントも注入します。WebKitではCDPによる実入力注入2件が対象外で、Touch Eventsによるピンチや指筆記は別途検証します。

### 確認結果（2026年11月18日）

Chromium・WebKitで、iPadサイズの安全領域、全画面切替後のツール維持、全画面API非対応時の表示、動画を選択したときだけ配置メニューが出ること、ズーム後もメニューの大きさを保つことを確認しています。動画は小さいShorts枠での縦長再生、再生中の拡大と復元、全画面切替後も同じプレーヤーで再生を続けることを検証しています。筆記では低筆圧、離筆時の線の末尾、部分消し、選択移動・拡大縮小、Undo/Redo、バックアップ復元を検証しています。1000%表示で高精細なPDF画像を維持し、近くへ移動したときに同じ画像を使うことも確認しています。

利用者よりiPadでのYouTube再生成功の報告があります。**今回の全画面表示と動画の配置メニューはiPad実機未検証です。** 講義前に次を確認してください。

- 「連続」で上下にスクロールし、「1ページずつ」で横スワイプできること。
- Apple Pencilの筆圧・線の追従・手のひら接触時の誤描画と、ペン／消しゴムの切り替え。
- 全画面表示でPDFの領域が広がり、筆記・動画配置の編集と資料メニューを使えること。
- ピンチの追従が滑らかで、ピンチ・縦横回転後も書き込み位置が合っていること。
- 使用予定のYouTube動画をページ内で再生・一時停止・シークできること。
- Safariを閉じた後の復元と、ファイルAppからのZIPバックアップ保存・復元。
- 実際のAirPlay／HDMI接続でPDF・筆記・動画・レーザーが投影されること。

## GitHub Pages

`.github/workflows/pages.yml`がmainへのpushでユニット・Chromium/WebKit統合テスト・型検査・ビルドを実行し、成功した成果物をPagesへ配信します。PRでは検証のみ実行します。

他のアカウントで公開する場合は、新規GitHubリポジトリを作成してソースをpushし、Settings → Pages → Sourceで**GitHub Actions**を選びます。Actionsからワークフローを実行し、deployジョブのURLを開いてください。秘密鍵やAPIキーは不要です。教材PDFやバックアップをリポジトリへcommitしないでください。

## データ設計と第2段階

`Project`は資料メタデータとページの配列、`Page`は元PDFのasset ID・元ページ番号・表示基準サイズ・手書き・動画を持ちます。座標はPDF.jsの**回転適用済み、scale=1のページ表示座標（左上原点）**です。画面上のCSSピクセルや端末サイズに依存しません。ページごとにPDF Canvas・手書きCanvas・保存しないレーザーCanvasを分離し、動画も同じ座標変換で重ねます。

クラウド同期は未実装です。第2段階ではIndexedDBリポジトリ層の上にSupabase等の認証・Storageと変更履歴を追加し、Microsoft OAuth、オフライン送信キュー、資料ごとのrevision、楽観的ロック、競合コピーを設計します。安全なログインや認可がないままクラウドへ教材を送る実装は含めていません。

技術資料: [PDF.js](https://mozilla.github.io/pdf.js/examples/)、[YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference)、[GitHub Pages Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
